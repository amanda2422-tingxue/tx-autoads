// JOIN 顺序（确保依赖正确：creatives 依赖 ads，benchmarks 依赖 adsets） const JOIN_ORDER = ['campaigns', 'adsets', 'ads', 'creatives', 'benchmarks']; interface ReportQueryBody { dimensions: string[]; metrics: string[]; } // 如果有过滤条件涉及特定字段，也加入对应 JOIN const f = body.filters || {}; if (f.campaignIds?.length) neededJoins.add('campaigns'); if (f.countryCodes?.length || f.adSetIds?.length || f.audienceTemplates?.length || f.radarTypes?.length) neededJoins.add('adsets'); 已知限制与后续优化方向

当前版本的已知限制
1. 投放人维度：当前 ad_campaigns 表没有 created_by/operator 字段和 users 表关联，如需此维度需先补字段。
2. 活跃广告数：该指标需要实时统计 ads.status='active'，不是 performance 历史聚合，暂未纳入。
3. 数据量：统一使用 level='ad' 的最细粒度数据，如 ad 级数据量极大（日数十万条），建议在 AdPerformance 上再加 (level, date, adset_id) 复合索引。
4. 图表：当前只有表格，后续可按维度自动生成为趋势图/柱状图。
