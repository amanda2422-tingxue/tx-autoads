## 五、V4.1 完成的关键变更（2026-04-24）

### 1. M4 规则引擎核心上线

- 完整重写 `ruleEngine.service.ts`（~700 行），实现条件解析、目标自动发现、Meta API 实时推送
- 精简 `checkRules.ts`（148行→55行），统一入口 `RuleEngineService.runAllActiveRules()`
- 新增 EPC/盈利比（profitability）指标体系，基于 CountryBenchmark 国家单价计算
- 修复国家代码解析 bug：优先取 adSet.countryCode，回退到 campaign.countryRadarConfig
- 修复时间窗口 bug：取所有 conditions 中最大的 timeWindow，而非仅用第一个

### 2. R1/R2 默认规则注入

- R1：spend ≥ $0.75 AND conversions == 0 → 自动暂停（24h 窗口，无冷却）
- R2：spend ≥ $3.00 AND CPA > $0.25 → 自动暂停（24h 窗口，24h 冷却）
- 通过种子脚本创建，同时修复 BD ctr_threshold 异常（0.8 → 0.008）

### 3. Cron 链式执行优化

- 将规则检查与数据同步串联：syncPerformanceData() → checkAutomationRules()
- 移除独立的 5 分钟规则检查 Cron，统一为 15 分钟周期
- 确保规则始终基于最新同步数据决策

### 4. 前端 Rules 页面增强

- 新增 EPC、payout、profitability 到指标映射
- 预设规则模板从 R3/R5 替换为 R1/R2
- targetIds 支持留空（提示"应用到所有活跃对象"）
- 测试结果弹窗展示 EPC、CPC、profitability、country

### 5. 测试端点升级

- `/api/rules/:id/test` 支持自动发现模式（targetIds 为空时自动查找活跃对象）
- 使用 getMaxTimeWindow() 统一时间窗口计算
- Dry-run 验证: 35 个活跃广告全部正确评估，0 误触发

### V3 历史变更（2026-04-21）

- 批量创建向导 4 步重构 + 开始创建按钮 Bug 修复
- CBO/ABO 预算策略 + 6 种 Campaign Objective
- Meta API 推送全链路打通（图片上传、粉丝页授权）
- 受众预置模板 + 文案库双列选择

## 七、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| Meta Access Token 过期 | 推送功能中断 | 已采用 System User Token（永不过期） |
| Facebook 个人号被封 | 不影响系统运行 | Token 绑定 BM 而非个人号 |
| 图片上传大量占用带宽 | 推送速度变慢 | 实现 image_hash 缓存，避免重复上传 |
| API 速率限制 | 数据同步延迟 | 实现批量请求 + 指数退避重试 |
| 数据库性能 | 数据量大时查询慢 | 添加索引、分页优化 |
